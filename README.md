## Подготовка

Нужны Node.js и npm. В корне проекта выполните:

```bash
npm install
npx playwright install
```

## Запуск тестов

Запустить все тесты во всех настроенных браузерах:

```bash
npm test
```

Запустить конкретный файл:

```bash
npx playwright test tests/search-page.spec.ts
```

Полезные режимы:

```bash
npm run test:ui       # интерактивный режим
npm run test:headed   # показать окно браузера
npm run test:debug    # пошаговая отладка
npm run test:report   # открыть HTML-отчёт
npm run lint          # проверить код ESLint
```

## Тест-кейсы

Документ описывает сценарии, которые уже реализованы в `tests/main.spec.ts` и `tests/search-page.spec.ts`. Это документация текущего покрытия, а не список дополнительных проверок.

### Общие условия запуска

- Стенд: `https://icons8.com/icons`.
- Браузеры по конфигурации Playwright: Chromium (Desktop Chrome), Firefox (Desktop Firefox), WebKit (Desktop Safari).
- Тесты запускаются параллельно; на CI используется один worker и до двух повторов упавшего теста.
- Перед сценарием поиска вызывается `prepareIcons8Consent`: если появляется окно согласия, необязательные разрешения отключаются и выбор подтверждается.

### TC-01 — Страница каталога иконок отвечает успешно

**Источник:** `tests/main.spec.ts`  
**Приоритет:** высокий  
**Тип:** smoke / доступность страницы

**Предусловия:** доступен сайт `icons8.com`; браузер запущен.

**Шаг 1.** Перейти на `https://icons8.com/icons`.  
**Ожидаемый результат:** получен HTTP-ответ с успешным статусом.

### TC-02 — Поиск `cat` открывает результат с загруженным превью иконки

**Источник:** `tests/search-page.spec.ts`  
**Приоритет:** высокий  
**Тип:** функциональный / поиск и просмотр результата

**Предусловия:** доступен сайт `icons8.com`; браузер запущен. Перед тестом выполняется подготовка consent через общий helper.

**Шаг 1.** Открыть страницу каталога. Если отображается окно согласия, отключить необязательные разрешения и подтвердить выбор.  
**Ожидаемый результат:** страница каталога открыта; окно согласия скрыто (если оно показывалось).

**Шаг 2.** Найти поле поиска `[data-test="search-input"]`.  
**Ожидаемый результат:** поле поиска отображается.

**Шаг 3.** Ввести `cat` и нажать Enter.  
**Ожидаемый результат:** открывается страница результатов поиска.

**Шаг 4.** Проверить адрес страницы.  
**Ожидаемый результат:** адрес равен `https://icons8.com/icons/set/cat`.

**Шаг 5.** Найти первый результат `[data-test="grid-icon"]` и открыть его.  
**Ожидаемый результат:** первый результат отображается и открывает превью.

**Шаг 6.** Дождаться отображения превью.  
**Ожидаемый результат:** отображается изображение или SVG-анимация.

**Шаг 7.** Проверить загрузку отображённого варианта: для изображения — непустой `src` и `naturalWidth > 0`; для SVG-анимации — видимость SVG.  
**Ожидаемый результат:** изображение загружено либо SVG-анимация видима.

## Ответы на вопросы

**Какой AI-инструмент использовали и чем он помог?**

Использовала Codex с моделью Luna Medium. Он помог быстрее разобраться с задачей и подготовить прототип E2E-теста на Playwright.

**Пришлось ли исправлять сгенерированный код?**

Да. Я упростила и привела код в порядок, убрала лишние комментарии и проверила локаторы на сайте. Ещё пришлось разобраться, как обрабатывать окно согласия на cookies: я добавила в тест шаг с настройками приватности на случай, если окно появится.

### Сложности и решения

#### Окно согласия на cookies

При первом открытии сайта появлялось окно, которое перекрывало страницу и мешало взаимодействовать с поиском. Сначала я попробовала установить дефолтные куки для тестов, но не смогла определить, какие именно куки управляют этим окном. Поэтому добавила в тест обработку самого диалога: ожидание его появления и поиск кнопок по селекторам, после чего подтверждаются выбранные настройки.

#### Гидратация страницы

При первом посещении тест иногда успевал ввести запрос в поле до того, как клиентский JavaScript завершал инициализацию страницы. После гидратации введённое значение сбрасывалось. В текущем варианте эту задержку перекрывает ожидание окна согласия, поэтому тест успевает дождаться готовности страницы. Это упрощённое решение и осознанный костыль. Для более надёжной синхронизации я бы добавила явное ожидание завершения инициализации Nuxt; в крайнем случае рассмотрела бы ожидание стабилизации сетевых запросов.
