# Инструкции для ИИ-агента

## Проект

- Это набор UI-тестов для Icons8 на TypeScript и Playwright.
- Перед изменениями изучи связанные тесты, helper-файлы и `playwright.config.ts`.
- Сохраняй существующий стиль форматирования и не добавляй зависимости без необходимости.

## Тесты

- Пиши тесты через `@playwright/test`.
- Группируй импорты: сначала библиотеки, затем файлы проекта; между группами оставляй пустую строку.
- Внутри группы импортов проекта располагай пути по удалённости от текущего файла: сначала ближайшие (`./`), затем более удалённые (`../`, `../../`).
- Предпочитай устойчивые локаторы: роли, доступные имена и `data-test` атрибуты. Не привязывайся к динамическим CSS-классам без необходимости.
- Для ожиданий используй Playwright assertions (`expect(locator)...`), а не фиксированные `waitForTimeout`.
- Отделяй блоки проверок `expect` пустой строкой от соседнего кода: до и после блока assertions (например, перед `return`, условием или следующим действием) оставляй пустую строку. Несколько связанных `expect` внутри одного блока размещай подряд.
- Повторно используй `tests/helpers/consent.ts` для подготовки consent. Не дублируй обработку consent в отдельных тестах.
- Если результат может отображаться в нескольких форматах, например изображением или SVG-анимацией, учитывай все поддерживаемые варианты.
- Не отключай проверки линтера и не меняй общую конфигурацию ради одного теста без явной причины.

## Команды

- Все тесты: `npm test`
- Один файл: `npx playwright test tests/<имя-файла>.spec.ts`
- Интерактивный режим: `npm run test:ui`
- Линтер: `npm run lint`

Запускай проверки, относящиеся к изменению, и сообщай, какие именно команды были выполнены.

## Границы изменений

- Меняй только файлы, нужные для запроса.
- Не создавай коммиты и не отправляй изменения в удалённый репозиторий без прямой просьбы.
- Не утверждай, что тесты или другие проверки прошли, если они не запускались.
